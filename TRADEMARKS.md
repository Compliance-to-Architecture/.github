The ™ glyph denotes a claimed-but-not-registered mark. Use of the
glyph on output produced by a conforming implementation of the
framework is **discouraged** — the framework's conformance test
(`test/conformance.test.mjs`) explicitly forbids ™/®/© in framework
manifest metadata so that downstream OSCAL / JSON-LD / SBOM consumers
receive clean machine-readable data.

In documentation, marketing, and human-facing copy, the ™ glyph is
appropriate where the mark is being asserted as the original
publisher's identifier.

## What you can call your implementation

If you build an implementation of the framework, you may say:

> "Built on the Compliance-to-Architecture Framework"
> "Conforms to the Compliance-to-Architecture spec v\<X\>"
> "An open-source implementation of \<framework-aspect\>"

You **may not**:

- Claim or imply Regunav Inc. endorses your implementation
- Use **Code Constitution™** or **ReguNav™** as your implementation's name
- Use the marks in a way that could cause consumer confusion
